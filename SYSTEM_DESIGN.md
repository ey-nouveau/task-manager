# Системный Дизайн (System Design): Universal Workspace & Admin Panel

## 🌟 Видение продукта
Наше приложение — это не просто Trello-клон. Это **универсальная админка и единое рабочее пространство (All-in-One Workspace)**. Цель проекта — создать мощный «storage всего»: задач, документации, клиентских баз, аналитики и настроек. 

Главные ориентиры по UX/UI: **Notion** (гибкость данных), **Trello/Linear** (скорость работы с задачами), **Monday/Airtable** (табличные базы данных).

---

## 🏗 Архитектура Фронтенда
*   **Стек:** React 19, TypeScript, Vite, Ant Design (кастомизированный).
*   **Стейт-менеджер:** Zustand (разбитый на слайсы: `useBoardStore`, `useDocsStore`, `useAppStore`).
*   **Роутинг:** `react-router-dom` (HashRouter для статики, но логически разделен на страницы).
*   **Стиль:** Темная тема по умолчанию, 35/65 Split Layout (верхняя фиолетовая зона управления, нижняя темная зона контента), 30+ переменных пастельных цветов.
*   **Адаптив:** Компонент `<Responsive>` и хук `useIsMobile` для conditional rendering.

## 📚 5 Ключевых Страниц (Модулей) Системы

### 1. 📊 Dashboard (Главный Дашборд / Аналитика)
**Роль:** Командный центр. Дает верхнеуровневое понимание, что происходит в системе.
*   **Визуал:** Сетка карточек (Grid) с пастельными цветами. Разделение экрана 35/65. В шапке — интерактивный график (например, транзакции или активность).
*   **Функционал:**
    *   Отображение ключевых метрик (Кол-во задач, Пользователи, Доходы, Активность).
    *   Графики в реальном времени.
    *   Тогглы быстрых действий (включить/выключить режим мониторинга).
*   **Сценарии пользователя:**
    *   Пользователь заходит в приложение -> Видит общую сводку за день/неделю.
    *   Клик по карточке метрики переводит на соответствующую таблицу (например, клик на "Tasks Done" кидает в Board с фильтром `status=done`).
*   **API Контракт:** 
    *   `GET /api/metrics/dashboard` -> Возвращает агрегированные цифры для карточек.

### 2. 📋 Task Board (Канбан-доска)
**Роль:** Управление процессами, задачами и спринтами.
*   **Визуал:** Горизонтально скроллящиеся колонки (To Do, In Progress, Review, Done).
*   **Функционал:**
    *   Полный CRUD задач с оптимистичными обновлениями (UI реагирует мгновенно, бэк обновляется в фоне).
    *   Модальное окно задачи: редактирование названия, богатого описания, статуса, исполнителей.
    *   *(В будущем)* Drag & Drop карточек между колонками.
    *   Система тегов/лейблов (с использованием наших пастельных цветов).
*   **Сценарии пользователя:**
    *   Менеджер быстро накидывает скелеты задач через инпуты внизу колонок.
    *   Разработчик открывает задачу, меняет статус, закрывает модалку -> статус улетает на бэк.
*   **API Контракт:**
    *   `GET /api/tasks`, `POST /api/tasks`, `PUT /api/tasks/:id`, `DELETE /api/tasks/:id`.

### 3. 🗃 Universal Database (Табличный вид / Справочники)
**Роль:** Хранилище «не-задач». Аналог Airtable или баз данных Notion.
*   **Визуал:** Бесконечная таблица (Data Grid) с типизированными колонками.
*   **Функционал:**
    *   Хранение любой информации: инвентарь, список сотрудников, CRM-база клиентов, транзакции.
    *   Сортировка, фильтрация и группировка по колонкам.
    *   Разные типы ячеек: Текст, Число, Дата, Выпадающий список (Status), Привязка к пользователю.
*   **Сценарии пользователя:**
    *   Добавление новой строки как новой записи в БД.
    *   Inline-редактирование ячеек (двойной клик -> ввод -> Enter -> отправка `PATCH` на бэк).
*   **API Контракт:**
    *   `GET /api/collections/:name` (получить схему и данные).
    *   `PATCH /api/collections/:name/rows/:id`.

### 4. 📝 Knowledge Base (Документация / Wiki)
**Роль:** База знаний команды. Статьи, регламенты, заметки.
*   **Визуал:** Слева — дерево документов (вложенные папки), справа — чистый лист (Rich Text Editor).
*   **Функционал:**
    *   Иерархическая структура (страница внутри страницы).
    *   Блочный редактор (как в Notion): поддержка Markdown, вставка изображений, таблиц, кода.
    *   Автосохранение (Debounce при вводе текста).
*   **Сценарии пользователя:**
    *   Пользователь создает "Регламент разработки".
    *   Пишет текст, нажимает `/` для вызова меню блоков.
    *   Текст сохраняется в базу в формате JSON (Block-based) или Markdown каждые 2 секунды без лоадеров.
*   **API Контракт:**
    *   `GET /api/docs/tree` (структура дерева).
    *   `GET /api/docs/:id` (контент страницы).
    *   `PUT /api/docs/:id` (автосохранение).

### 5. ⚙️ Settings & Admin Panel (Настройки и Доступы)
**Роль:** Управление всем воркспейсом (супер-админка).
*   **Визуал:** Вертикальные табы слева (General, Members, Roles, API/Webhooks), формы справа.
*   **Функционал:**
    *   Управление участниками (Members): инвайты, удаление, смена ролей (Admin, Editor, Viewer).
    *   Генерация API-токенов для внешних интеграций.
    *   Кастомизация воркспейса (загрузка логотипа, смена глобальных тем).
*   **Сценарии пользователя:**
    *   Владелец заходит в Members, нажимает "Invite", вводит email. На бэке создается инвайт-ссылка.
    *   Отзывает API-токен старого скрипта.
*   **API Контракт:**
    *   `GET /api/workspace/members`, `POST /api/workspace/invites`.
    *   `POST /api/auth/tokens`.

## 🚀 План Имплементации (Roadmap)

1.  **Фаза 1: Укрепление Ядра (Мы здесь)**
    *   ✓ Дизайн-система (Адаптив, Цвета).
    *   ✓ Настроенный CI/CD (GitHub Pages).
    *   ✓ Базовый Канбан (Board) и Дашборд.
2.  **Фаза 2: Universal Database (Таблицы)**
    *   Создание переиспользуемого компонента DataGrid.
    *   Подключение к бэкенду для хранения произвольных коллекций.
3.  **Фаза 3: Knowledge Base (Документация)**
    *   Интеграция редактора (например, Editor.js или BlockNote).
    *   Реализация древовидной структуры файлов в UI.
4.  **Фаза 4: Управление доступами (RBAC)**
    *   Внедрение авторизации (JWT / Session).
    *   Страница Settings и ограничение видимости кнопок (Admin Only).
5.  **Фаза 5: Drag & Drop и Реалтайм**
    *   Подключение `dnd-kit` для карточек и строк таблиц.
    *   *(Опционально)* WebSocket для того, чтобы изменения одного юзера мгновенно появлялись у других.
