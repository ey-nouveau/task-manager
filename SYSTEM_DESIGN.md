# Системный дизайн Trello-подобной доски задач

Этот документ описывает основные бизнес-сценарии работы приложения (клиента) и то, какие действия ожидаются от системы (бэкенда) для их реализации.

## 1. Инициализация (Загрузка доски)
**Действие пользователя:** Открывает приложение (URL).
**Поведение клиента:** 
- Показывает лоадер (Spinner).
- Делает запрос на получение всех задач.
- Раскладывает задачи по колонкам (`todo`, `in-progress`, `done`) в зависимости от поля `status`. Если статус пустой — кидает в `todo`.
- Скрывает лоадер, показывает доску.

**Требуемый API Endpoint:**
- **GET** `/api/tasks`
- **Ответ:** 
  ```json
  [
    {
      "id": 1,
      "title": "Купить молоко",
      "description": "2 пакета",
      "status": "todo",
      "created_by": "User",
      "assigned_to": "User"
    }
  ]
  ```

---

## 2. Создание новой задачи
**Действие пользователя:** Пишет название в инпут под любой из колонок и нажимает "Add" (или Enter).
**Поведение клиента:**
- Блокирует инпут (опционально) или сразу добавляет скелет задачи на доску.
- Отправляет запрос на бэкенд с `title` и `status` (ID колонки, где был нажат Add).
- После успешного ответа (с полученным из БД настоящим ID) добавляет полноценную задачу в стейт.

**Требуемый API Endpoint:**
- **POST** `/api/tasks`
- **Тело (Request):** `{"title": "Название", "status": "todo"}`
- **Ответ (Response):** Возвращает созданный объект задачи с новым сгенерированным `id`.

---

## 3. Редактирование задачи (Название и Описание)
**Действие пользователя:** Кликает на карточку задачи -> Открывается модальное окно. Пользователь меняет заголовок или пишет длинное описание.
**Поведение клиента:**
- Оптимистичное обновление: текст мгновенно меняется на экране (без лоадеров).
- Отправляется фоновый запрос на бэкенд с измененными полями.
- Если бэкенд возвращает ошибку, клиент должен откатить изменения обратно (Revert).

**Требуемый API Endpoint:**
- **PUT** (или **PATCH**) `/api/tasks/:id`
- **Тело:** `{"title": "Новое название", "description": "Новый текст"}`

---

## 4. Перемещение задачи по доске (Смена статуса)
**Действие пользователя:** Нажимает стрелочку вправо/влево на карточке (в будущем - Drag and Drop).
**Поведение клиента:**
- Оптимистичное обновление: карточка мгновенно перепрыгивает в соседнюю колонку на экране.
- Клиент вычисляет новый статус (например, был `todo` -> стал `in-progress`).
- Отправляет фоновый запрос на бэкенд.
- Если ошибка -> откатывает карточку в предыдущую колонку.

**Требуемый API Endpoint:**
- **PUT** (или **PATCH**) `/api/tasks/:id`
- **Тело:** `{"status": "in-progress"}`
*(По сути это та же ручка, что и для редактирования)*

---

## 5. Удаление задачи
**Действие пользователя:** Нажимает кнопку удаления (корзинка на превью или красная кнопка в модалке).
**Поведение клиента:**
- Карточка мгновенно исчезает из интерфейса (оптимистичное обновление).
- Отправляется запрос на удаление.
- Если модалка была открыта - она закрывается.
- Если бэкенд упал с ошибкой - карточка возвращается на место.

**Требуемый API Endpoint:**
- **DELETE** `/api/tasks/:id`
- **Ответ:** Статус `204 No Content` или `200 OK`.

---

## Резюме по Бэкенду
Тебе потребуется всего один роутер (контроллер) на сущность `tasks`, который должен обрабатывать 4 базовых метода:
1. `GET /api/tasks`
2. `POST /api/tasks`
3. `PUT /api/tasks/:id`
4. `DELETE /api/tasks/:id`
